# ESP8266 Smart Clock — 项目文档

> ESP-12F NTP时钟 + OLED显示 + 闹钟 + Web配置 + 锂电池电量监测

**固件版本**：v1.0.0  
**开发团队**：CaiYang Team  
**开发环境**：VSCode + PlatformIO (Arduino框架)

---

## 一、硬件引脚连接

| 引脚 | GPIO | 连接设备 | 说明 |
|------|------|----------|------|
| D1 | GPIO5 | OLED SCL (I2C时钟) | 0.96寸SSD1306 OLED 128×64 |
| D2 | GPIO4 | OLED SDA (I2C数据) | 0.96寸SSD1306 OLED 128×64 |
| D5 | GPIO14 | 有源蜂鸣器(+) | 闹钟响铃，低电平触发 |
| D6 | GPIO12 | 恢复出厂设置按键 | 按键另一端接GND，长按5秒清除所有配置 |
| A0 | ADC | 锂电池电压检测 | 通过分压电路(2:1)接入3.7V-4.2V锂电池 |
| 3.3V | — | OLED VCC | 供电 |
| GND | — | OLED GND / 蜂鸣器(-) / 按键 / 电池GND | 公共地 |

### I2C地址
- OLED显示屏：`0x3C`

### ADC电池检测
- ESP8266 ADC量程：0-3.3V (10bit, 0-1023)
- 分压比：2:1（代码中 `BATTERY_DIVIDER_RATIO = 2.0`，根据实际电阻修改）
- 电量映射：3.7V = 0%，4.2V = 100%

## 二、EEPROM存储布局

| 地址 | 长度 | 内容 | 说明 |
|------|------|------|------|
| 0-63 | 64字节 | WiFi SSID | 用户配置的WiFi名称 |
| 64-127 | 64字节 | WiFi密码 | 用户配置的WiFi密码 |
| 128 | 1字节 | 闹钟1 小时 | 0-23，0xFF表示未设置 |
| 129 | 1字节 | 闹钟1 分钟 | 0-59，0xFF表示未设置 |
| 130 | 1字节 | 闹钟2 小时 | 0-23，0xFF表示未设置 |
| 131 | 1字节 | 闹钟2 分钟 | 0-59，0xFF表示未设置 |
| 132 | 1字节 | Magic标记 | `0xAA` = 已配置过，非首次开机 |

## 三、运行流程

### 阶段1：上电初始化

```
上电 → 引脚初始化 → OLED初始化 → 读取EEPROM(WiFi/闹钟/Magic标记)
```

- 蜂鸣器引脚设为OUTPUT，初始低电平
- 恢复出厂按键引脚设为INPUT_PULLUP（内部上拉）
- OLED通过I2C初始化 (地址0x3C)
- 从EEPROM加载WiFi账号密码、闹钟设置
- 检查Magic标记判断是否首次开机

### 阶段2：WiFi连接判断

**情况A — 首次开机 / 无WiFi配置（Magic标记 ≠ 0xAA）：**
```
OLED显示欢迎页 → 进入主循环 → 等待用户通过AP配置WiFi
```

- 显示内容：欢迎信息 + AP名称(esp8266) + AP密码(caiyang123456) + AP地址(192.168.4.1)
- AP模式常开，用户手机连接AP后浏览器访问配置页面
- 每5秒刷新欢迎页
- 用户通过Web页面保存WiFi后，ESP自动重启，进入情况B

**情况B — 已有WiFi配置（Magic标记 = 0xAA）：**
```
OLED显示欢迎页 → 尝试连接WiFi(最长60秒) → 成功/失败
```

- 连接期间Web服务器也在响应（`server.handleClient()`）
- **连接成功**：
  - 关闭AP模式（`WiFi.softAPdisconnect(true)` + `WiFi.mode(WIFI_STA)`）
  - OLED显示欢迎页（此时显示WiFi网络中的IP地址，如192.168.1.105）
  - 等待10秒让用户看到IP地址
  - 进入主时钟页面
- **连接失败（60秒超时）**：
  - OLED显示连接失败页（显示用户配置的WiFi名）
  - 显示10秒后自动进入主时钟页面（此时AP模式仍开启）

### 阶段3：SNTP时间同步

```
configTime()配置NTP → 后台自动同步 → 年份>2010视为已同步
```

- 使用ESP8266内置SNTP功能（不依赖外部NTPClient库）
- NTP服务器：`ntp.aliyun.com` / `pool.ntp.org`
- 时区：UTC+8（中国标准时间）
- 同步前OLED显示 `NTP Sync...`
- 同步后显示真实日期 `YYYY-MM-DD`

### 阶段4：主循环（主时钟页面）

每100ms循环执行：

1. **Web服务器处理** — 响应WiFi配置/闹钟设置/设备信息请求
2. **蜂鸣器更新** — 非阻塞式，闹钟响铃期间Web服务不中断
3. **OLED显示刷新**：
   - 第一行：日期 + WiFi状态(✓/✗) + 电量百分比
   - 第二行：大字体时分秒
   - 第三行：两个闹钟时间（带闹钟图标，未设置显示NULL）
4. **闹钟触发** — 时间匹配时蜂鸣器响5次（400ms开/400ms关）
5. **恢复出厂按键检测** — D6引脚长按5秒清除EEPROM并重启

## 四、Web服务

### 访问方式

| 阶段 | 访问地址 |
|------|----------|
| 首次开机 / WiFi未连接 | `http://192.168.4.1`（需先连接AP热点） |
| 已连接WiFi | `http://设备IP`（OLED上显示的IP地址） |

### 页面路由

| 路由 | 方法 | 功能 |
|------|------|------|
| `/` | GET | WiFi配置页面 |
| `/alarm` | GET | 闹钟设置页面 |
| `/info` | GET | 设备信息页面 |
| `/save` | POST | 保存WiFi配置（保存后ESP重启） |
| `/setAlarms` | GET | 保存闹钟设置 |

### WiFi配置页面 (`/`)
- 输入框：WiFi名称、WiFi密码
- 提交后保存到EEPROM，ESP自动重启
- 连接成功后关闭AP模式

### 闹钟设置页面 (`/alarm`)
- 闹钟1：两个数字输入框（时: 0-23，分: 0-59）
- 闹钟2：两个数字输入框（时: 0-23，分: 0-59）
- 留空 = 不启用（OLED显示NULL）
- 提交后保存到EEPROM

### 设备信息页面 (`/info`)
- 固件版本、开发团队、芯片ID、Flash大小、可用内存、设备IP、运行时间

## 五、OLED显示布局

```
┌────────────────────────────────────┐
│ 2026-06-03 WiFi✓         78%      │  ← 第1行：日期 + WiFi状态 + 电量
│                                    │
│         14:30:25                   │  ← 第2行：2倍字体时分秒
│                                    │
│ ⏰1:07:00        ⏰2:NULL          │  ← 第3行：两个闹钟(带图标)
└────────────────────────────────────┘
```

- WiFi✓ = 已连接用户WiFi，WiFi✗ = 未连接
- NTP未同步时日期行显示 `NTP Sync...`
- 闹钟未设置时显示 `NULL`

## 六、恢复出厂设置

- **触发方式**：D6(GPIO12)引脚按键长按5秒（按键接GND）
- **执行操作**：清除EEPROM全部数据 → 重启
- **重启后**：进入首次开机流程，AP模式开启，等待重新配置

## 七、开发过程记录

### 第1轮：基础框架搭建
- 建立ESP8266 + PlatformIO项目结构
- 实现OLED显示（SSD1306 I2C）、NTP时间同步（NTPClient库）、蜂鸣器、EEPROM存储
- Web服务：WiFi配网页面 + 闹钟设置页面
- 问题：静态IP硬编码、日期/电量硬编码、闹钟阻塞式delay

### 第2轮：功能完善
- 增加EEPROM Magic标记实现首次开机检测
- 增加3个OLED页面：欢迎页、连接失败页、主时钟页
- Web页面改为响应式布局（侧边栏菜单：WiFi配置/闹钟设置/设备信息）
- 增加ADC电池电量读取（3.7V-4.2V线性映射）
- 增加恢复出厂设置按键（D6长按5秒）
- 蜂鸣器改为非阻塞模式（不阻塞Web服务）

### 第3轮：AP连接问题修复
- **问题**：手机连上AP热点但无法访问192.168.1.10
- **原因**：自定义AP IP(192.168.1.10)与DHCP分配网段不一致
- **修复**：改用ESP8266默认AP网段 `192.168.4.1`
- 增加页面状态管理（currentPage: 0=欢迎/1=失败/2=主时钟）
- 欢迎页和失败页不再一闪而过

### 第4轮：Web页面内存优化
- **问题**：浏览器访问返回空白页
- **原因**：完整HTML页面(~2.5KB)拼接成一个String，ESP8266堆内存不足
- **修复**：改用分块发送（`server.sendContent()`），精简CSS

### 第5轮：精简重构
- 用户要求：去掉华丽页面，最简洁中文界面
- 去掉侧边栏布局，改为简单的顶部导航链接
- 闹钟从4个减为2个
- 时分秒字号改为2倍（用户自行调整）
- 连接用户WiFi后关闭AP模式，使用STA IP
- 欢迎页显示WiFi网络中的实际IP地址

### 第6轮：日期bug修复
- **问题**：OLED显示 `-1814665-08-26` 等错误日期
- **原因**：NTPClient库的 `getEpochTime()` 返回无效值，`gmtime` 解析出垃圾数据
- **修复**：去掉NTPClient库，改用ESP8266内置SNTP（`configTime()` + `localtime()`）
- 系统时间自动同步，`localtime()` 直接返回正确时区的日期时间
- NTP未同步时显示 `NTP Sync...`，同步后显示真实日期
- `platformio.ini` 中移除NTPClient库依赖

### 第7轮：OLED显示优化
- WiFi图标改为文字 "WiFi" + 对号✓/叉号✗
- 增加闹钟图标（8x8位图）
- 电量百分比右对齐，避免与WiFi状态重叠
- 电池图标简化为矩形+正极
